O Que Sabemos vs O Que Falta?

✅ O Que Você Já Domina

  • Criar nó na Heap com malloc(sizeof(No)).
  • Inserir chaves: menores à esquerda e maiores à direita.
  • Busca binária com tempo médio O(log n).
  • Contar nós pares e percorrer a árvore.

⚠️ O Grande Risco da Exclusão

E se um registro precisar ser removido da árvore? (Ex.: cancelamento de matrícula, venda de produto).

❌ NUNCA faça apenas free(no)! Se o nó tiver filhos ou subárvores abaixo dele, seus ramos inteiros ficarão perdidos no limbo da RAM, gerando lixo de memória e quebrando os ponteiros da árvore.
CONCEITO FUNDAMENTAL

A Regra de Ouro da BST

Toda e qualquer remoção deve preservar esta regra sagrada 100% íntegra.

📌 Invariante de Busca

Para QUALQUER nó com chave X:

  • Todos os nós à ESQUERDA são estritamente MENORES que X.
  • Todos os nós à DIREITA são estritamente MAIORES que X.

💡 Regra de ouro: Ao remover um nó, a árvore precisa ser "remendada" de forma que a busca binária continue funcionando para todos os elementos restantes.

Árvore Modelo Perfeita: < 50 à esquerda | > 50 à direita
CASO 1 • O MAIS TRANQUILO

Remover Nó Folha (Zero Filhos)

Analogia: podar uma folha na ponta do galho. Nada abaixo cai ou se quebra.

🌱 Cenário

O nó que queremos excluir não tem nenhum filho: raiz->esq == NULL && raiz->dir == NULL.

📝 Passo a Passo Cirúrgico

1 Localize o nó folha via busca binária.
2 Desaloque a memória com free(raiz).
3 Retorne NULL para que o ponteiro do pai aponte para o vazio.
// Caso 1 em C: if (raiz->esq == NULL && raiz->dir == NULL) { free(raiz); return NULL; // Pai recebe NULL }
Clique no botão acima para ver o nó folha ser liberado e o ponteiro virar NULL.
CASO 2 • ADOÇÃO DO NETO

Remover Nó com 1 Único Filho

Analogia de Família: Quando o pai se ausenta, o avô adota o neto diretamente!

👪 Cenário

O nó possui apenas o filho da esquerda OU apenas o da direita.

📝 Mecânica dos Ponteiros

1 Salve o endereço do neto num ponteiro temporário: temp = raiz->dir.
2 Desaloque o pai com free(raiz).
3 Retorne o neto para que o avô aponte diretamente para ele!
// Caso 2 em C (só tem filho direito): if (raiz->esq == NULL) { No* temp = raiz->dir; // Salva o neto free(raiz); // Libera o pai return temp; // Avô adota o neto! }
O nó 30 tem apenas o filho 40. Clique para ver a ponte de adoção direta.
CASO 3 • O CASO NOBRE

Remover Nó com 2 Filhos

O dilema: Existem 2 subárvores inteiras abaixo dele. Quem tem direito de assumir o lugar?

👑 A Sucessão ao Trono Real

Imagine que o rei faleceu. Quem pode sentar no trono sem violar a lei do reino?

👉 O SUCESSOR IMEDIATO: O menor elemento que ainda é maior que ele!

🔍 A Bússola do Sucessor:
1. Dê 1 passo para a DIREITA (vai para os maiores);
2. Vá TUDO para a ESQUERDA até o final da linha!
✨ O nó 60 é o sucessor: maior que 30, 20, 40 e menor que 70, 80!
SIMULADOR DO CASO 3

O Truque da Substituição

Não desconectamos a árvore. Apenas copiamos o valor do sucessor e apagamos a folha lá embaixo!

🪄 Os 3 Passos da Mágica

1 Encontre o sucessor: No* temp = menorNo(raiz->dir);
2 Copie o valor dele para a raiz: raiz->conteudo = temp->conteudo;
3 Mande remover o sucessor na direita (ele é folha ou caso 2!).
// Caso 3 em C: No* temp = menorNo(raiz->dir); // Acha o 60 raiz->conteudo = temp->conteudo; // Raiz vira 60 raiz->dir = remover(raiz->dir, temp->conteudo); // Apaga o 60 antigo
Clique no botão acima para ver o 60 assumir a raiz e sua cópia na base ser liberada.
CÓDIGO COMPLETO DISSECADO

A Função remover() em C

Observe como as atribuições raiz->esq = remover(...) remendam a árvore no retorno.

No* remover(No* raiz, int valor) { if (raiz == NULL) return NULL; // Chave não encontrada ou árvore vazia // 1. NAVEGAÇÃO RECURSIVA ATÉ LOCALIZAR O VALOR if (valor < raiz->conteudo) raiz->esq = remover(raiz->esq, valor); else if (valor > raiz->conteudo) raiz->dir = remover(raiz->dir, valor); else { // 2. NÓ ENCONTRADO! QUAL É O CASO? if (raiz->esq == NULL) { // Caso 1 (folha) ou Caso 2 (só filho dir) No* temp = raiz->dir; free(raiz); return temp; } else if (raiz->dir == NULL) { // Caso 2 (só filho esq) No* temp = raiz->esq; free(raiz); return temp; } // Caso 3: Tem DOIS filhos! Busca o menor da subárvore direita No* temp = menorNo(raiz->dir); raiz->conteudo = temp->conteudo; // Copia valor do sucessor raiz->dir = remover(raiz->dir, temp->conteudo); // Remove a duplicata folha } return raiz; }

SEGURANÇA DA MEMÓRIA RAM

Por que a Pós-Ordem Salva a Vida?

Veja por que a Pós-Ordem é a ÚNICA maneira correta de dar free() sem quebrar o programa.

❌ O Erro Clássico de Quem Começa

Muitos alunos escrevem a destruição na ordem errada:

free(raiz); // 💀 ERRO GRAVE! destruir(raiz->esq); // raiz já foi apagada da RAM! destruir(raiz->dir); // Segmentation Fault / Travamento!

Se você apaga o pai primeiro, os ponteiros para os filhos viram ponteiros fantasmas (Dangling Pointers).

✅ A Solução em Pós-Ordem

Primeiro liberamos as subárvores inteiras, e por último a raiz:

void destruirArvore(No* raiz) { if (raiz == NULL) return; destruirArvore(raiz->esq); // 1. Limpa filho esquerdo destruirArvore(raiz->dir); // 2. Limpa filho direito free(raiz); // 3. Só agora libera a si mesmo! }
APLICAÇÃO NA INDÚSTRIA & COMPILADORES

Árvores de Expressão: Como Compiladores Calculam?

Como a relação entre Pré, Em e Pós-Ordem dá vida às calculadoras e compiladores de linguagens de programação.

🧮 Expressão: (3 + 5) * (10 - 2)

  • Em-Ordem (Infixa): 3 + 5 * 10 - 2
    Formato humano natural. Exige parênteses para não ambíguo.
  • Pré-Ordem (Prefixada / Notação Polonesa): * + 3 5 - 10 2
    Usada em linguagens funcionais como Lisp e Scheme. O operador vem antes dos operandos.
  • Pós-Ordem (Posfixada / Notação Polonesa Reversa - RPN): 3 5 + 10 2 - *
    Usada em calculadoras HP, Bytecode Java (JVM) e WebAssembly com Pilha! Zero parênteses!

💡 Insight para o Desenvolvedor: Ao caminhar em Pós-Ordem, empilhe números. Ao encontrar um operador, desempilhe dois e calcule. Não há parênteses e a execução é instantânea!

Árvore Sintática da Expressão: (3 + 5) * (10 - 2) = 64
ANÁLISE DE ALGORITMOS & EFICIÊNCIA

Complexidade: Do O(log n) ao Pesadelo O(n)

O que acontece quando os dados chegam já ordenados em uma Árvore Binária de Busca ingênua?

⚠️ A Árvore Degenerada ("Vara de Pescar")

Se você inserir na BST as chaves em ordem crescente: 10, 20, 30, 40, 50, cada nó será sempre maior que o anterior e cairá na subárvore direita.

Resultado: A árvore vira uma Lista Simplesmente Encadeada disfarçada, perdendo todo o benefício da busca binária!

Operação Árvore Balanceada Pior Caso (Degenerada)
Busca O(log n) O(n)
Inserção O(log n) O(n)
Remoção O(log n) O(n)
Degeneração: Altura h = n. Buscar o 50 exige 5 saltos em vez de 2!
