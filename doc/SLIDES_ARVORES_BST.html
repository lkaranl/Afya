⚖️ O Ponto de Partida

Por que Precisamos de Árvores?

O dilema clássico entre Vetores Ordenados e Listas Encadeadas que vimos na N1

🔍 Vetor com Busca Binária

• Busca: ⚡ Excelente em O(log n).

• Inserção / Remoção: 🐢 Terrível em O(n) (exige deslocar centenas de milhares de vizinhos na memória).

🔗 Lista Encadeada Dinâmica

• Inserção: ⚡ Flexível e rápida na Heap.

• Busca: 🐢 Lenta em O(n) (impossível pular para o meio; precisa andar nó por nó).

💡 A Solução BST: Nós dinâmicos na Heap com ponteiros que garantem busca E inserção rápidas em O(log n)!

💡 Conceito Chave

Busca Binária vs. Árvore Binária

A diferença fundamental que todo desenvolvedor precisa saber

🔍 Busca Binária

É um ALGORITMO: uma estratégia matemática de divisão e conquista.

[10] [20] [30] [40] [50] ↑ meio = v[(0+4)/2]

⚠️ Inserir novo elemento exige empurrar blocos vizinhos de lugar!

🌳 Árvore Binária de Busca

É uma ESTRUTURA DE DADOS: a forma física como os nós moram na RAM.

(30) / \ (20) (50) \ (25)* ← só aloca e aponta!

⚡ Insere em O(log n) sem empurrar nenhum dado existente!

🌍 Aplicação Prática

Onde as Árvores Rodam no Mundo Real?

Sua infraestrutura de trabalho sustentada por árvores a cada segundo

🗄️ Bancos de Dados (PostgreSQL, MySQL)

Índices B-Tree acham 1 CPF entre 100 milhões de clientes em ~1 milissegundo (apenas 27 saltos de disco).

🌐 DOM da Web & React Virtual DOM

O HTML é literalmente uma árvore em memória. O React faz percursos em árvores para atualizar só o que mudou na tela.

📦 Compactação de Arquivos (ZIP, MP3)

A Árvore de Huffman atribui caminhos curtos (2-3 bits) para letras frequentes e encolhe 10 MB para 3 MB.

🎮 Motores de Jogos 3D (Unreal, Unity)

Árvores BSP e Octrees descartam tudo o que está fora da visão da câmera para manter 120 FPS.

📐 Vocabulário Técnico

Anatomia de uma Árvore

Na computação, as árvores crescem de cima para baixo

[ 50 ] ← 👑 Raiz (Root) / \ [ 30 ] [ 70 ] ← 🔹 Nós Internos / \ / \ [20] [40] [60] [80] ← 🍃 Folhas (Leaves) ════════════════════════════════════ ◀ Menores à Esq | Maiores à Dir ▶
👑 Raiz (Root): O nó do topo sem pai. Início obrigatório de toda rota.
🍃 Folha (Leaf): Nós terminais com esq == NULL && dir == NULL.
📏 Altura (Height): O caminho mais longo até a folha mais distante.
💻 Engenharia em C

A Estrutura do Nó na Memória

Como modelamos o nó da BST em C com ponteiros auto-referenciados

typedef struct No { int valor; struct No* esq; // menores (<) struct No* dir; // maiores (>) } No; No* criarNo(int valor) { No* novo = (No*) malloc(sizeof(No)); novo->valor = valor; novo->esq = NULL; novo->dir = NULL; return novo; }

📌 Regra de Ouro: Todo nó recém-criado nasce como folha: seus ponteiros esq e dir começam sempre como NULL.

🔄 Algoritmo Central

A Inserção Recursiva

Sempre começa da Raiz e desce até encontrar um ponteiro vazio

No* inserir(No* raiz, int valor) { // 1. Caso Base: achou o espaço vazio! if (raiz == NULL) { return criarNo(valor); } // 2. Se menor, desce pela ESQUERDA if (valor < raiz->valor) { raiz->esq = inserir(raiz->esq, valor); } // 3. Se maior, desce pela DIREITA else if (valor > raiz->valor) { raiz->dir = inserir(raiz->dir, valor); } return raiz; }
🌟 O Efeito Mágico

Os 3 Percursos em Árvores

Como visitar todos os nós de uma estrutura não-linear

1. Em-Ordem

Esq ➔ Raiz ➔ Dir

A Mágica: Visita os nós exatamente em ordem crescente natural!

2. Pré-Ordem

Raiz ➔ Esq ➔ Dir

Ideal para clonar ou salvar a árvore em disco no mesmo formato exato.

3. Pós-Ordem

Esq ➔ Dir ➔ Raiz

Mandatório para o `free`: desaloca os filhos antes de apagar o pai!

💡 O Raciocínio

Numa BST, os menores números moram sempre à esquerda. Você precisa olhar para a direita alguma vez?

Nunca! Basta andar para a esquerda enquanto existir filho!
int buscarMenor(No* raiz) { if (raiz == NULL) return -1; No* atual = raiz; while (atual->esq != NULL) { atual = atual->esq; // segue à esquerda } return atual->valor; }
